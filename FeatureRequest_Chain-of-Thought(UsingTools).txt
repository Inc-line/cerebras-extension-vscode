2. Retrieving Relevant Context (Executing Tools)
This section changes significantly. The findRelevantContext function (and getActiveEditorContext) are no longer called before the first API request. Instead, they are executed if and when the LLM requests them via a tool call response.

The extension's main logic needs a loop to handle potential tool calls:

javascript
// Simplified interaction loop
async function handleUserQuery(userQuestion, conversationHistory, context /*, other params */) {
    let currentHistory = [...conversationHistory]; // Copy history for this turn
    currentHistory.push({ role: 'user', content: userQuestion });

    let maxTurns = 5; // Safety break for tool call loops
    let turn = 0;

    while (turn < maxTurns) {
        turn++;

        // 1. Prepare the prompt including tool descriptions and current history
        const toolDescriptions = getToolDescriptions(); // Load the JSON descriptions
        const prompt = preparePromptForApiWithTools(currentHistory, toolDescriptions);

        // 2. Call the Cerebras API
        const response = await makeCerebrasApiCall(prompt, context.globalState.get('wscode.apiKey'), /* selectedModel */);
        const responseContent = response.choices[0].message.content; // Adjust based on actual API response structure
        const toolCalls = response.choices[0].message.tool_calls; // Check for tool calls

        if (!toolCalls || toolCalls.length === 0) {
            // No tool calls, LLM provided the final answer
            console.log("[Cerebras] Received final answer.");
            currentHistory.push({ role: 'assistant', content: responseContent });
            // Update UI, save final history, etc.
            await saveHistory(context, currentHistory); // Save the full turn history
            displayAnswerInWebview(responseContent);
            return; // Exit the loop
        }

        // 3. Handle Tool Calls
        console.log(`[Cerebras] Received tool call request:`, toolCalls);
        // Add the assistant's request message to history
        currentHistory.push({ role: 'assistant', content: null, tool_calls: toolCalls });

        for (const toolCall of toolCalls) {
            const functionName = toolCall.function.name;
            const functionArgs = JSON.parse(toolCall.function.arguments); // Arguments are often JSON strings
            let functionResultContent;

            try {
                if (functionName === 'getActiveEditorContext') {
                    functionResultContent = getActiveEditorContent(); // Your existing function
                } else if (functionName === 'findRelevantContext') {
                    // Ensure workspaceCodeContext is loaded if using indexing
                    const workspaceCodeContext = context.workspaceState.get('wscode.workspaceCodeContext') || {};
                    if (Object.keys(workspaceCodeContext).length === 0 && !functionArgs.query) {
                         functionResultContent = "Workspace has not been indexed yet. Cannot search.";
                    } else if (!functionArgs.query) {
                         functionResultContent = "Error: Search query parameter is missing.";
                    }
                     else {
                        functionResultContent = findRelevantContext(functionArgs.query, workspaceCodeContext);
                    }
                } else {
                    console.warn(`[Cerebras] Unknown tool called: ${functionName}`);
                    functionResultContent = `Error: Tool '${functionName}' not found.`;
                }
            } catch (error) {
                 console.error(`[Cerebras] Error executing tool ${functionName}:`, error);
                 functionResultContent = `Error executing tool ${functionName}: ${error.message}`;
            }


            // Add the tool result message to history for the next API call
            currentHistory.push({
                role: 'tool',
                tool_call_id: toolCall.id, // Important to link result to the call
                content: functionResultContent
            });
        }
        // Loop back to call the API again with the tool results included in the history
    }

    // If loop finishes without returning, something went wrong (e.g., too many tool calls)
    console.error("[Cerebras] Max tool call turns exceeded.");
    displayErrorInWebview("Assistant got stuck in a loop trying to use tools. Please try rephrasing your question.");
    // Save the partial history for debugging?
    await saveHistory(context, currentHistory);
}

Summary of Changes (Tool Use Adaptation):
Define Tools: Identify functions like getActiveEditorContext and findRelevantContext as tools. Create JSON descriptions for them according to Cerebras API specs.
Modify Interaction Flow: Implement a loop in the main request handler (handleUserQuery) to:
Send the user query + history + tool descriptions to the API.
Check the response for tool call requests.
If tools are called: Execute the corresponding local functions, get the results.
Add the tool results back into the conversation history.
Call the API again with the updated history.
Repeat until the API returns a final answer without tool calls.
Update Prompting: Change preparePromptForApi to include tool descriptions and instruct the model on how/when to use them. Ensure the history formatting correctly includes tool calls and results. Crucially, implement robust context length management.
Tool Execution Logic: Write the code to parse tool call requests from the API, map them to your local functions (like findRelevantContext), execute them, and handle potential errors.
State Management: Use workspaceState for history. If using workspace indexing, also use workspaceState to store the index data accessed by the findRelevantContext tool. Add a command to trigger indexing.
Overall Thoughts:

This is a powerful approach!

Pros:
Gives the LLM more agency to request specific information only when needed, potentially leading to more relevant context use.
Can handle more complex queries that require information from multiple sources (editor + workspace search).
Aligns with modern LLM interaction patterns.
Cons:
Increased Complexity: The interaction logic becomes significantly more complex due to the multi-turn request/response/tool-execution loop. Error handling is more involved.
Latency: Each tool call adds at least one extra round trip to the API, increasing the time to get the final answer.
Context Window Management: Managing the context window becomes harder as tool calls and results add to the conversation history length. Careful truncation strategies are essential.
API Costs: More API calls might mean higher costs, depending on the pricing model.
Recommendation: This is a worthwhile evolution of the feature. Start by implementing tool use with just the getActiveEditorContext tool, as it's simpler and doesn't require indexing. Once that works, you can add the findRelevantContext tool and the associated workspace indexing mechanism if the added complexity is justified by the feature requirements. Remember to consult the Cerebras Tool Use documentation carefully for the exact API request/response formats.
